30 Networking Commands

The troubleshooting toolbox: 21 Windows commands and 9 Linux essentials, each with its job and an example.

The first rule of troubleshooting: know what you're looking at. These thirty commands cover every classic diagnosis — from "is my cable even working" to "who is listening on port 443".

Windows — the 21 essentials

#CommandWhat it does
1ipconfig /allFull IP, DNS, DHCP and MAC configuration — the first thing to look at
2ipconfig /releaseRelease the DHCP lease
3ipconfig /renewRequest a new DHCP lease
4ipconfig /flushdnsClear the DNS resolver cache
5ping -t 8.8.8.8Continuous ping (Ctrl+C to stop) — watch a flaky link live
6ping -n 4 example.comFour pings (Linux uses -c 4)
7tracert example.comHop-by-hop route to a host (traceroute on Linux)
8pathping example.comRoute plus per-hop loss and latency — slow but thorough
9nslookup example.comDNS query; add a DNS server as a second argument to ask a specific one
10netstat -anoAll connections and listeners with their PIDs; -b adds the executable name (admin)
11arp -aThe ARP cache — IP-to-MAC mappings on your LAN
12route printThe routing table — where does traffic actually go?
13getmac /vMAC addresses by adapter
14net use \\fileserver\shareConnect to an SMB share; run alone to list current mappings
15telnet example.com 443Classic TCP port test (the Telnet client is an optional Windows feature)
16ssh user@hostEncrypted remote shell — OpenSSH client is built into Windows
17curl.exe -I https://example.comHTTP status and headers (in PowerShell 5.1, use curl.exe — plain curl is an alias)
18Test-NetConnection example.com -Port 443PowerShell: ping plus TCP port test in one line
19Test-Connection example.com -Count 4PowerShell ICMP ping
20Resolve-DnsName example.comPowerShell DNS records
21Get-NetAdapterAdapter status, link speed and MAC — is the interface even up?

Linux / macOS — the 9 essentials

#CommandWhat it does
22ip addrInterface addresses — the modern replacement for ifconfig
23ip routeRouting table — replaces route -n
24dig example.com +shortDNS lookup; @server selects a specific resolver
25ss -tulpnListening TCP/UDP sockets with PIDs — the modern netstat
26nmap -sT -p 443 192.168.1.10TCP port scan — only against systems you own or are authorised to test
27tcpdump -i eth0 -nn port 443Packet capture — needs root, and the interface name varies
28wget https://example.com/fileDownload a file
29ifconfig -aLegacy interface list — still everywhere, but ip addr is current
30systemctl status networkingNetworking service status (RHEL/Fedora often use NetworkManager instead)
Worth remembering

On Linux, netstat, ifconfig and arp are legacy — the current tools are ss, ip addr and ip neigh. tcpdump and full ss -p output need root. And scan only what you're allowed to scan.
