VLAN — Configuration and Trunking

One physical switch acting as several virtual switches — how it works, how to configure it, and how the traffic flows between them.

A VLAN (Virtual Local Area Network) splits one physical switch into several logical switches. Devices in different VLANs cannot see each other at Layer 2 — as if they were on different hardware — until a router connects the two worlds. The reasons are security (finance can't sniff engineering), isolation and smaller broadcast domains.

802.1Q — the tag

A trunk carries frames from several VLANs on one cable. To tell them apart, each frame gets a 4-byte 802.1Q tag inserted after the source MAC address: a 16-bit TPID (0x8100 = "this frame is tagged"), a 3-bit priority field, one DEI bit, and the 12-bit VLAN ID — which is why the range stops at 4094.

Every trunk also has a native VLAN (default: VLAN 1): frames that arrive without a tag belong to it. Both ends of the trunk must agree on the native VLAN — a mismatch can create loops. And the native VLAN is the chink in the armour: VLAN hopping attacks abuse it (double-tagging a frame so the outer tag is stripped and the inner one delivers the packet to a protected VLAN). The mitigations: keep hosts off VLAN 1, set the native VLAN to an unused ID, tag the native VLAN where supported, disable DTP auto-negotiation and unused ports, and prune trunks to only the VLANs they need.

Inter-VLAN routing — the bridge between worlds

Devices in different VLANs cannot talk at Layer 2 — that's the point. The bridge is a router, connected by a trunk. The classic design is router-on-a-stick: one trunk, and one subinterface per VLAN, each acting as that VLAN's gateway:

interface GigabitEthernet0/0
 no shutdown
interface GigabitEthernet0/0.10
 encapsulation dot1q 10
 ip address 192.168.10.1 255.255.255.0

Repeat the subinterface for VLAN 20, and the router routes between 192.168.10.x and 192.168.20.x. The alternative is a Layer 3 switch, which does the same job in hardware with an SVI per VLAN (interface vlan 10 + ip routing).

Configuration — the whole recipe

Switch(config)# vlan 10
Switch(config-vlan)# name SALES
Switch(config)# interface GigabitEthernet0/1
Switch(config-if)# switchport mode access
Switch(config-if)# switchport access vlan 10
Switch(config)# interface GigabitEthernet0/24
Switch(config-if)# switchport mode trunk
Switch(config-if)# switchport trunk allowed vlan 10,20
Switch# show vlan brief
Switch# show interfaces trunk

Interface naming varies by platform (Gi0/1 on older switches, Gi1/0/1 on newer ones) — check with show interfaces status.

Voice VLAN — one port, two VLANs

An IP phone sits between the wall and the PC, sharing one access port. The voice VLAN solves it: the phone's traffic is tagged onto the voice VLAN (switchport voice vlan 20), while the PC's data stays untagged on the access VLAN. One cable, two worlds.

Best practices

Never use VLAN 1 for user traffic. Change the native VLAN on trunks. Prune trunks to the VLANs they actually carry (switchport trunk allowed vlan). Disable unused ports and DTP negotiation. And document every VLAN: ID, name, subnet, gateway and purpose — the next technician will thank you.
